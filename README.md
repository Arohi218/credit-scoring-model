# Task 1 — Credit Scoring Model

## Objective
Predict a binary educational label (`creditworthy`: 1 or 0) from financial-history features.

## Dataset
`generate_demo_data.py` creates 1,600 **synthetic** rows. It is for pipeline testing only and is not real bank/customer data. For a real project, use a properly licensed dataset such as the UCI Default of Credit Card Clients dataset; map its outcome carefully and document its limitations.

Features: age, annual income, debt-to-income ratio, credit utilization, late payments in the last 12 months, credit-history years, employment type, home ownership.

## Setup (Python 3.10+ recommended)
```bash
python -m venv .venv
# Windows: .venv\Scripts\activate
# macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt
python generate_demo_data.py
python train.py --data data/credit_demo.csv
```

## What it does
- 75/25 stratified train/test split
- median/mode imputation, scaling and one-hot encoding
- Logistic Regression and Random Forest comparison
- accuracy, precision, recall, F1, ROC-AUC, confusion matrix
- saves the best-by-F1 pipeline to `outputs/credit_scoring_model.joblib` and metrics to `outputs/metrics.json`

## Interpretation and limitations
Synthetic labels are generated by a toy formula; results only validate that the code runs. Do not use this for actual credit decisions. Real credit scoring requires consent, legal compliance, fairness testing, explainability, robust validation, privacy safeguards and human review.
